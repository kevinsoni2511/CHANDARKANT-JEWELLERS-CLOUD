# Chandarkant Jewellers Cloud — Enterprise Security Specification

## 1. Threat Model & Key Assets

| Asset | Potential Threat | Mitigation Architecture |
|---|---|---|
| **Multi-Tenant Data** | Cross-tenant data leakage / horizontal privilege escalation | Automatic Global Scopes on all Tenant models; composite DB unique keys; token-to-tenant verification. |
| **Financial Records & Ledgers** | Silent tampering, unauthorized ledger editing | Immutable journal voucher entries; no direct UPDATE on posted entries; audited reversal vouchers only. |
| **Metal Inventory & Stock** | Fictitious stock additions / phantom sales | Compulsory SKU/Barcode assignment; single-source state transitions; physical stock audit trails. |
| **API Endpoints** | Brute force, credential stuffing, SQL injection | Laravel Sanctum token auth, rate limiting (ThrottleRequests), Eloquent parameterized queries, strict FormRequests. |
| **AI Copilot** | Prompt injection, SQL execution via LLM | No direct SQL generated by LLM; strictly bounded Function Calling / Tool execution via predefined domain services. |

---

## 2. Authentication & Authorization Architecture

- **Token Security**: Laravel Sanctum tokens with customizable expiration.
- **Password Standards**: Bcrypt hashing with cost factor 12.
- **RBAC**: Enforced at Controller and Policy layer (`authorize('view', $item)`).
- **Tenant Context**: Injected via `TenantContextResolver` middleware. Tokens contain `tenant_id` claim, cross-checked against database records on every request.

---

## 3. Data Integrity & Decimal Safety

- **No Float Arithmetic**: All weights and monetary totals computed via PHP `BCMath` or PostgreSQL `NUMERIC` types.
- **DB Transactions**: Multi-table operations (e.g., Sale Invoice + Stock Update + Double Entry Ledger + Customer Balance) execute inside atomic database transactions (`DB::transaction()`). Any failure triggers immediate automatic rollback.
